# 方案 · 工具集扩展（可靠性封装）

> 提出：2026-10-15
> 项目：[[20261014-deepseek-agent-desktop]]
> 动机：工具调用的**表达力**已够（local_cmd 是 PowerShell，图灵完备），
> 但**可靠性**不足 —— 编辑现有文件时，模型要在一次调用里同时处理
> 正则元字符 / 编码 / 全局替换 / 转义四件事，经常只做对三件。

---

## 零、问题的本质

不是「缺工具调用机制」，是**缺工具层的可靠性封装**。

| 操作 | 现在怎么做 | 坑 |
|---|---|---|
| 改一行 | `(Get-Content x -Raw) -replace 'a','b' \| Set-Content x` | 正则元字符 / 编码 ANSI / 全局替换 / 转义 |
| 改一行（备选） | `write_file` 整文件重写 | 全量 token + 静默丢内容 |
| 看大文件 | `Get-Content` | 无行号 / 无分页 / 编码乱码 |

分界线：**输出是新内容（够）vs 输出是已有内容的修改（不够）**。

## 二、实现顺序（分 4 批）

**第 1 批（打地基）**：`read_file` + `replace_in_file` + `list_dir` ✅ **已完成（2026-10-16）**
→ 让 Agent 从「能写新文件」变成「能改代码」

实现落在 `gad_engine/tools_fs.py`（纯逻辑，零依赖），接线在
`protocol.py`（分类）与 `agent.py::_execute`（分发）。

三个关键设计（都是实测踩坑后的结论）：
  1. **replace_in_file 用字面量而非正则** —— 代码里的 `$` `\` `[` `(`
     全是正则元字符，让模型多转义一层是给它加一道它经常做错的题。
  2. **全程 bytes 读写** —— `Path.write_text` 在 Windows 上会把 `\n`
     翻译成 `\r\n`，导致 CRLF 文件被写成 `\r\r\n`（实测 bug）。
     逐字节写才能保证「只改该改的，其余一个字节不动」。
  3. **编码只认 UTF-8，不猜** —— 猜错编码写文件，症状是「中文注释变
     乱码」，而这一步极难被归因。非 UTF-8 明确报错。

测试：`test_tools_fs.py`（36 项，纯逻辑）+ `test_fs_pipeline.py`（27 项，
解析链路）+ `test_fs_exec.py`（18 项，执行层接线）。全量 19 个测试文件全绿。

顺带修的边界：`classify` 里 `read_file_x` 会被误判成 `read_file` ——
已收紧为「工具名后必须紧跟 `:` 或行尾」。

**第 2 批（看懂代码库）**：`grep` + `glob` + `todo` ✅ **已完成（2026-10-16）**

实现落在 `gad_engine/tools_search.py`（grep / glob）与
`gad_engine/tools_todo.py`（清单）。

关键设计：
  1. **纯 Python，不依赖 ripgrep/fd** —— 代价是大目录慢，所以有结果数
     上限 + 文件大小上限兜底。宁可少给几条，也不让一次搜索卡住引擎。
  2. **遍历时剪枝** —— 用 os.walk 原地改 dirnames 跳过 node_modules /
     .git / .venv 等，而不是 rglob 走进去再过滤。
  3. **grep 支持 fixed=1** —— 搜 `$foo` / `a[0]` 这类含正则元字符的串时，
     模型不必自己转义。与 replace_in_file 用字面量同一个理由。
  4. **todo 按对话隔离** —— 它是「当前这件事」的进度，不是跨会话的长期
     事实（那个是 memory）。每个对话一份 Markdown，用户能直接打开看。

测试：`test_tools_search.py`（20 项）+ `test_tools_todo.py`（17 项，纯逻辑）
+ `test_search_exec.py`（14 项，执行层接线）。全量 22 个测试文件全绿。

**待做**：第 3 批（job 管理 / ask_user / run_tests）、第 4 批（MCP / 危险命令确认）。

**第 3 批（长期任务）**：`job` 管理 + `ask_user` + `run_tests` ✅ **已完成（2026-10-16）**

  * `job` —— 后台作业管理（`gad_engine/jobs.py`）。把 `local_cmd:async` 从
    「发射后不管」变成「可查询」：每个后台命令有 id，可 `job:list` /

  * 路径逃逸检测 ✅ **已完成** —— `safety.check_path_escape` + `_write_file`。
    判据是 resolve 后的 Path 是否真在允许根**之下**，不是字符串前缀 ——

  * MCP 客户端 ✅ **已完成（2026-10-16）** —— `gad_engine/mcp.py`。

      - 单一 `mcp` 工具 + 动态子命令（`mcp:list` / `mcp:<server>/<tool>`），

### C 类 · 结构化编辑（2026-10-16 完成）

  * `multi_edit` —— 单文件**多处**编辑，一次落盘。
  * `apply_patch` —— **多文件** unified diff，原子改动。

  **核心价值是原子性，不是省调用**：连续调 N 次 replace_in_file，
  第 3 次失败时前 2 次已落盘 —— 文件处于「改了一半」的中间态，
  可能语法都不成立。这两个工具先把所有编辑在内存里试算，
  **全部成功才写**，任一处失败则整体不动。

  复用 `tools_fs` 的底层（编码探测 / 换行处理 / 原子写），
  保证三个编辑工具的「写文件」语义完全一致。

  apply_patch 只做「修改已有文件」—— 新增/删除由 write_file 等负责。
  不解析行号做模糊定位（行号会漂移），按**精确内容**匹配 hunk。

  测试：`test_tools_patch.py`（29 项）+ `test_patch_exec.py`（10 项）。

  **顺带修的坑**：`apply_patch` 的 `root=` 不能复用 `split_path_args`
  —— 那个要求 key=value 前有空白，而这里整个 spec 就是 `root=...`，
  实测 `root` 会整个丢失 → 文件找不到。改用专用 `_parse_root`。
  同一个坑在 `run_tests` 的 `cmd=` 上踩过一次 —— 已是第二次。

### E 类 · 网络（2026-10-16 完成）

  * `web_fetch` —— 读指定 URL，HTML 转纯文本。**本地 HTTP**，
    与账号风控无关，能精确指定 URL，结果可落盘。
  * `web_search` —— 主动搜索，返回结果列表（依赖 DuckDuckGo
    HTML 版，无需 API key，可用性不由我们保证）。

  **与服务端搜索的区别**：本客户端已能「联网」，但那是 DeepSeek
  模型在服务端搜 —— Agent 无法指定要读哪个 URL、结果进不了本地
  文件、且与账号风控绑定。本模块是**这台电脑**直接发 HTTP，
  解决的是「精确读某个网页」这个真实缺口。

  **零新依赖** —— 用标准库 urllib + html.parser。这两个工具不需要
  TLS 指纹伪装（那是对抗 DeepSeek 风控用的，普通网站不需要）。

  诚实边界：不做 JS 渲染（SPA 可能拿不到内容）、不做反爬对抗、
  只允许 http/https（拒绝 file:// 等）。

  测试：`test_tools_web.py`（26 项）+ `test_web_exec.py`（9 项），
  都用本地假 HTTP 服务器，不发真实外部请求。（新增 read_file / replace_in_file / list_dir /
grep / glob / todo:write / todo:read / job / ask_user / run_tests）。

**新增模块**：tools_fs / tools_search / tools_todo / tools_tests / jobs / safety。

**新增测试**：10 个测试文件，全量 29 个文件全绿。

### 对标「真 Agent」的补强（2026-10-16 起）

对比 Claude Code / Cline 这类成熟 Agent，本项目在**执行层**扎实，
但**认知层**与**安全控制层**有缺口。已补：

  * **并行工具执行** ✅ —— `_dispatch` 把**相邻的只读调用**并发
    （read_file / grep / glob / list_dir / todo:read / web_fetch /
    web_search）。有副作用的工具永远串行 —— 它们的顺序有语义。
    **为什么是「连续只读段」而非「所有只读调用」**：`[读A, 写B, 读C]`
    里读C 可能依赖写B，全并行会打乱语义。
    可在配置里用 `executor.parallel_reads = false` 关掉。
    测试：`test_parallel.py`（17 项，含真并发计时 / 顺序保持 /
    取消信号穿透 / 单跑异常不终止）。

  * **编辑前 diff 预览** ✅（2026-10-16）—— 三个编辑工具（replace_in_file / multi_edit / apply_patch）支持 `preview=1`：返回 diff 而**不写入**，确认后再去掉 preview 应用。
    `tools_diff.py` 是纯 diff 生成层（用标准库 difflib，不自己写算法）。
    编辑成功后也会附 `+X -Y` 摘要 —— 让你看到确实改了什么。
    测试：`test_tools_diff.py`（23）+ test_tools_patch 的 preview 用例。

  **待补**：编辑回滚 / 检查点、子 Agent 委派、中断恢复、权限分级。

## 三、每个新工具的改动点（统一四处）
