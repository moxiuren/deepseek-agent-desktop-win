# DeepSeek Agent Desktop · 界面设计方案 v1

> 2026-10-16 · 配套高保真原型：`docs/design/mockup.html`
> 方向：**克制专业 · 低饱和**（Linear / Cursor 气质）· **浅色为主**（保留深色扩展位）· 覆盖**全部窗口**

---

## 一、目标与约束

**目标**：在**不推翻现有配色体系**的前提下，重构信息架构与视觉层次，让界面既好看又好用。

**硬约束**（都来自现有代码，不是假设）：

| 约束 | 依据 |
|---|---|
| 配色不能乱改 | `App.xaml` 里那套灰阶是按 WCAG AA 逐条算过的（Ink 13.04:1 / InkSoft 6.05:1 / InkFaint 4.89:1，语义色 8.75–9.65:1）。改一个值就要重算一遍 |
| 语义色分两套，不可混用 | `*Fill` 给图形（≥3:1），`*Ink` 给文字（≥4.5:1）。历史上把亮色当正文色用过一次，「最要紧的字最看不清」 |
| 层次只能靠 1px 描边 / 极浅底色 / 字重 | 现有体系**一个阴影都没用**。加了阴影就要维护阴影令牌，且 WPF 下渲染成本不低 |
| 所有文字必须可选中 | 上一轮刚把 `TextBlock` 换成只读 `TextBox`，新控件不能退回 `TextBlock` |
| 字号缩放必须覆盖新控件 | `TextZoom.Walk` 靠遍历逻辑树 + `Tracked` 列表，新控件要在创建时登记 |
| 顶栏宽度预算已耗尽 | `MainWindow.xaml` 注释原文：「再往这一行加东西之前，先想清楚是收进『设置』、还是改成图标/菜单 —— 否则就是在推高最小可用宽度」 |

## 二、现状诊断

七条结构性问题，每条都有代码依据。

### 1. 顶栏是唯一的宽度瓶颈，而且是负循环

36px 高的一行里塞了 **9 个控件**：账号模式徽章、身份点+文字、信号点+文字、服务端忙点+文字、闸门、transport、模型下拉(158px)、思考下拉(92px)、联网勾选、刷新凭据、身份、设置。

XAML 注释自己记着这笔账：

> 右栈「最长文案」档从 703px 涨到 740px，MinWidth=1090 下 `TxtBusy` 被截断（需 64.2 得 54.6）—— audit 直接判 FAIL。把 MinWidth 提到 1120 后才重新通过。

**MinWidth 的历史是 1000 → 1060 → 1090 → 1120。** 每加一个功能就缩小一次可用设备范围 —— 这个方向不能继续。

### 2. 三个圆点没有语义

`DotAccount` / `DotSignal` / `DotBusy` 是三个 8px `Ellipse` + 一段文字。用户看到「信号 —」，不知道它指什么。

这是本应用最独特的部分 —— **风控雷达**（熔断信号、服务端忙计数、闸门状态）。但雷达没有刻度、没有解释，等于把最关键的信息藏在最不可读的形式里。

### 3. 状态与操作混在同一行

左边是纯状态（身份、信号、服务端忙），右边是状态+操作混排（闸门、transport、模型、思考、联网、刷新、身份、设置）。两类东西**视觉重量完全相同**，扫视时无法分层。

### 4. 监视器被降级成「切换视图」

从常驻第三栏改成「对话 / 监视器」二选一 —— 解决了密度问题，但引入了新问题：**看工具执行时看不见对话，看对话时看不见执行。**

对一个 agent 执行器来说，这两者是同一件事的两面。用户最需要的恰恰是「它一边说、一边做」的同时可见。

### 5. 对话流内部没有层次

`ConvPanel` 里正文、思考块、工具卡片按加入顺序堆叠，没有角色标签、没有间距节奏、没有轮次边界。一次 run 22 次工具调用，正文会被工具卡片冲散。

### 6. 输入区承载的信息太少

输入区只有：文本框、运行 / 取消本轮、解除熔断。

而「这轮用什么模型 / 开不开思考 / 联不联网」这些**每次发消息前都要确认的上下文**，却在顶栏最远端。

### 7. 设置是单列长滚动

`SettingsDialog` 780×800 里塞了 7 个 `RowDefinition`：说明卡 → 占位符警告 → 文字大小+显示思考 → 模板编辑框 → 预览 → 记忆 Expander → 操作条 → 状态条。

想找「文字大小」得滚到中部，且**不知道自己错过了什么**。

## 三、设计原则

### 原则 1：状态归状态，操作归操作

顶栏只放**关于「这个应用现在怎么样」**的东西；输入区只放**关于「这一轮要怎么做」**的东西。两类不再混排。

### 原则 2：时间线是唯一真相，但必须有层次

对话流是唯一的叙事线 —— 正文、思考、工具调用都在上面。但四类内容必须有**各自明确的形态**，让扫视时能一眼分出「它在说」和「它在做」。

### 原则 3：克制即专业

层次靠 **1px 描边 + 极浅底色 + 字重**，不靠阴影、渐变、大圆角。这条不只是审美 —— 它是现有体系已经验证过的、WPF 下渲染成本最低的做法。

### 原则 4：可选中、可缩放、可键盘

任何一段文字都能框选复制；`Ctrl+=` / `Ctrl+-` / `Ctrl+0` 只改字号不动窗口；关键动作有快捷键且**提示常驻可见**。

## 四、信息架构

从「一个顶栏 + 一块主区」改成**三层 + 一条上下文带**：

```
┌──────────────────────────────────────────────────────────────────┐
│ 顶栏 48px    会话名 ······              [健康胶囊] [身份] [设置]   │  ← 状态层
├──────────┬────────────────────────────────────┬──────────────────┤
│ 会话层    │  内容层                             │  运行层           │
│ 236px    │  对话流（唯一时间线）                 │  300px           │
│ 可折叠    │                                    │  可折叠           │
│          │  用户消息 / 助手正文                  │  时间线           │
│ 搜索      │  思考块（可折叠）                     │  引擎日志         │
│ 本地|网页版│  工具卡片（折叠成一行）                │  健康详情         │
│ 会话列表   │                                    │                  │
│ 新建对话   │                                    │                  │
├──────────┴────────────────────────────────────┴──────────────────┤
│ 输入区        [模型][思考][联网]                                    │  ← 上下文带
│              ┌──────────────────────────┐  [发送]                  │
│              └──────────────────────────┘                         │
│              Enter 发送 · Shift+Enter 换行 · Esc 取消本轮           │
└──────────────────────────────────────────────────────────────────┘
```

**关键取舍**：右栏从「切换视图」改成「可折叠常驻面板」。

- 宽窗口（≥1280px）：默认展开，对话与执行同时可见
- 窄窗口（<1280px）：默认收起，点标题栏图标展开
- 这样既保住了「同时可见」，又不会在小窗口上挤爆主区

## 五、布局与网格

| 区域 | 尺寸 | 折叠行为 |
|---|---|---|
| 窗口基准 | 1280 × 800 | — |
| MinWidth 目标 | **~860px** | 待 `--layout-audit` 验证 |
| 顶栏 | 48px 固定高 | 不折叠 |
| 会话层 | 236px 固定宽 | 可折叠至 0（留 40px 竖条，与现状一致） |
| 内容层 | 弹性，**正文最大宽 760px 居中** | — |
| 运行层 | 300px 固定宽 | 可折叠；<1280px 默认收起 |
| 输入区 | 自适应（文本框 min 76px） | 不折叠 |

**为什么正文要限宽 760px**：现在 `ConvScroll` 是全宽铺开，窗口一拉宽，一行能到 200 多个字符 —— 阅读时眼睛回扫距离过长。限宽 + 居中是最省事也最有效的可读性改进。

## 六、设计令牌

**配色一个值都没改**，只做了归类与三处补充。

### 底色与分隔

| 令牌 | 值 | 用途 | 状态 |
|---|---|---|---|
| `Bg` | `#F7F7F5` | 窗口底 | 沿用 |
| `Surface` | `#FFFFFF` | 卡片 / 主区 | 沿用 |
| `SurfaceAlt` | `#FBFBF9` | 侧栏 / 次级 | 沿用 |
| `Sunken` | `#F2F1EE` | 代码 / 工具输出块 | **新增** |
| `Line` | `#E4E2DB` | 描边 | 沿用 |
| `LineSoft` | `#EFEDE6` | 弱分隔 | 沿用 |

### 文字灰阶（均过 AA）

| 令牌 | 值 | 对比度 | 用途 |
|---|---|---|---|
| `Ink` | `#2C2C2A` | 13.04:1 | 正文 |
| `InkSoft` | `#5F5E5A` | 6.05:1 | 次要说明 |
| `InkFaint` | `#6E6C66` | 4.89:1 | 时间戳 / 元信息 |

### 语义色

| 组 | Fill（图形） | Ink（文字） | Soft（胶囊底） | 状态 |
|---|---|---|---|---|
| Ok | `#639922` | `#27500A` (8.75:1) | `#F1F7E8` | Soft 新增 |
| Warn | `#BA7517` | `#633806` (9.33:1) | `#FBF3E5` | Soft 新增 |
| Bad | `#E24B4A` | `#791F1F` (9.65:1) | `#FDEDEC` | Soft 新增 |
| Accent | `#185FA5` | `#0E3F70` | `#E6F1FB` | AccentInk 新增 |

> `*Soft` 是给**状态胶囊**用的极浅底。它只做背景，文字仍用 `*Ink` —— 所以对比度不受影响。

### 字号阶梯

| 字号 | 字重 | 颜色 | 用途 |
|---|---|---|---|
| 11px | 400 | InkFaint | 时间戳、元信息、图例 |
| 12px | 400 | InkSoft | 次要说明、列表副标题 |
| 13px | 400 | Ink | 正文、用户消息、输入框 |
| 13px | 600 | Ink | 会话名、小节标题 |
| 14px | 600 | Ink | 对话框标题 |
| 11.5px | mono | InkSoft | 工具输出、引擎日志、代码 |

字体：界面 **Segoe UI**（现状不变）；代码/日志 **Cascadia Mono**（现状是 `Consolas`，建议换 —— Cascadia Mono 是 Windows 11 默认等宽字体，字宽更规整）。

### 间距与圆角

- 间距（4px 基准）：`4 / 8 / 12 / 16 / 24 / 32`
- 圆角：`4`（芯片）/ `6`（按钮、输入框）/ `8`（卡片）/ `10`（面板、窗口）

## 七、组件规范

### StatusPill（状态胶囊）· 新增

把原来三个无名圆点合并成一个**有文字的**胶囊。三态：

| 态 | 底色 | 文字色 | 文案示例 |
|---|---|---|---|
| 正常 | OkSoft | OkInk | `● 运行正常` |
| 警告 | WarnSoft | WarnInk | `● 服务端忙 2/3` |
| 熔断 | BadSoft | BadInk | `● 熔断中 · 剩余 4h12m` |

- 高度 26px，圆角 13px，内边距 0 10px，字号 11.5px / 600
- **常态只占一个词**（约 90px），异常才变长 —— 宽度预算因此可控
- 点击展开健康面板（额度窗口、冷却倒计时、最近信号）

### ToolCard（工具卡片）· 重做

| 部位 | 折叠态 | 展开态 |
|---|---|---|
| 高度 | 34px | 34px + 输出区 |
| 左 | 状态图标（✓ 绿 / 转圈 蓝 / ✕ 红，14px） | 同 |
| 类型徽章 | 等宽小字 `local_cmd` / `read_file`，10.5px，带 1px 描边 | 同 |
| 摘要 | 等宽 11.5px，单行省略 | 同 |
| 右 | 耗时 `0.4s`，10.5px / InkFaint | 同 |
| 输出区 | 隐藏 | `Sunken` 底，等宽 11.5px，最大高 220px 可滚 |

**默认折叠**是这条的关键 —— 22 次工具调用压成 22 行，正文不再被冲散。

### ThinkingBlock（思考块）· 重做

- 折叠：`▶ 思考了 8 秒`（11.5px / InkFaint，整行可点）
- 展开：左侧 2px `LineSoft` 竖线 + 12.5px `InkSoft` 正文
- **默认折叠**；进行中自动展开（有实时内容可看时才值得占空间）

### MessageBlock（消息块）

| 角色 | 形态 |
|---|---|
| 用户 | `AccentSoft` 底 + `#D3E4F6` 描边 + 圆角 8 + 内边距 10/13 |
| 助手 | 无底色，左侧 2px `Line` 竖线 + 左内边距 13 |

两者都**左对齐**（不用右对齐气泡）—— 桌面 agent 应用里左对齐更利于扫视长内容，也避免正文宽度被气泡反复压缩。

### Chip（上下文芯片）· 新增

- 高度 24px，圆角 12px，1px `Line` 描边，底 `SurfaceAlt`
- 结构：`标签(灰) + 值(深色粗体) + ▾`
- 激活态（如联网开启）：`AccentSoft` 底 + `#C9DEF4` 描边 + `AccentInk` 文字

### SegmentedControl（分段控件）· 新增

「本地 / 网页版」从两个裸 `Button` 改成分段控件：`Sunken` 底槽 + 2px 内边距 + 选中项 `Surface` 底带极轻阴影。

**为什么值得改**：两个裸按钮看不出「二选一」，而现状注释里还专门写了「不用 ToggleButton，互斥状态自己维护迟早会漂」—— 分段控件把这个约束变成视觉上自明的。

### 其他

| 组件 | 规格 |
|---|---|
| Button · Primary | `Accent` 底，白字，600，高 30，圆角 6 |
| Button · Secondary | `Surface` 底，`Line` 描边，`InkSoft` 字 |
| Button · Icon | 30×30，圆角 6，hover 显 `SurfaceAlt` 底 + `Line` 描边 |
| SearchField | 高 30，圆角 6，左侧 13px 放大镜图标 |
| ConversationItem | 内边距 9/10，圆角 6；选中 `AccentSoft` + `AccentInk` 标题 |
| EmptyState | 居中，`InkFaint` 一句说明 + 一个主按钮 |

## 十、分期落地建议

按「风险从低到高、收益从高到低」排序。**每一期都能独立交付并验证**。

### P0 · 顶栏瘦身 + 输入区芯片（收益最高，风险最低）

- 删掉顶栏 8 个控件，合并成健康胶囊
- 模型/思考/联网挪进输入区芯片
- **直接效果**：MinWidth 有望从 1120 降到 ~900
- **验证**：`--layout-audit` 必须 0 FAIL；`--selfcheck` 退出码 0

### P1 · 对话流分层

- 消息块（用户/助手）、思考块默认折叠、工具卡片默认折叠
- **直接效果**：长任务不再被工具输出冲散
- **验证**：`--selfcheck` 的「可复制」断言要覆盖新块；`TextZoom` 要登记新控件

### P2 · 右栏常驻执行面板

- 把「切换视图」改成可折叠常驻列
- **风险点**：这是唯一会**增加** XAML 复杂度的一期，建议 P0/P1 稳定后再做

### P3 · 设置 / 身份对话框改版

- 左导航 + 内容区；身份对话框承载凭据详情

### P4 · 深色主题（预留）

- 现有颜色全部走语义变量 → 将来加一套深色值即可
- **前提**：P0–P3 期间不要引入硬编码颜色

## 十一、风险与待验证项

| 项 | 说明 |
|---|---|
| **MinWidth ~860 是估算** | 必须用 `--layout-audit` 实测。该门禁会把 `MinWidth` 本身也量进去，是唯一可信的判据 |
| 右栏常驻会增加复杂度 | P2 单独一期，不与 P0/P1 混提 |
| `TextZoom` 覆盖 | 新控件必须在创建时调 `TextZoom.Fresh()`，否则 Ctrl+= 对它无效（**静默失效**，不会报错） |
| 可复制覆盖 | 新块必须用只读 `TextBox`，不能用 `TextBlock`。上一轮刚踩过：`Children[i] = x` **不是替换语义**，会抛 `ArgumentException`，必须 `RemoveAt` + `Insert` |
| 折叠控件的缩放 | 收起的 `Expander` 内容不在可视树上，`TextZoom` 靠 `Tracked` 列表兜底 —— 新控件也要进这个列表 |
| Cascadia Mono 可用性 | Windows 10 可能未预装，需要 fallback 到 Consolas |
