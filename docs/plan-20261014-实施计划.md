## 一、前提与已知风险

### 必须解决的四个缺口（2026-10-14 查明）

| # | 缺口 | 真实网页版 | 原版直连 | 补法 |
|---|---|---|---|---|
| 1 | **TLS 指纹** | Chrome 真身 | .NET Schannel 裸奔 | `curl_cffi` + `impersonate` |
| 2 | **`x-hif-leim`** | 服务端下发，客户端回传 | 没带 | 抓包确认来源后回传 |
| 3 | **`x-hif-dliq`** | 存在 `localStorage` | 没处理 | 随 token 一起取 |
| 4 | **PoW 时序** | wasm + Worker 异步解 | C# 原生 67ms | 对齐缓存语义与求解节奏 |

### 不可回避的结构性风险

- **DeepSeek 没有匿名模式** —— 必须登录，封的是账号本身（Gemini 有访客模式可兜底）。
- **没有主动遥测通道** —— 只能事后刹车（等 40003），做不到事前预警。
- **历史事实** —— 原版直连「跑没多久就封号，封到一个时间点后自动解封」，
  说明触发的是**自动风控**（只看可量化信号），不是人工审核。

> **因此本计划的第一原则：先证明「补上四缺口后存活率是否改变」，再谈工程。**

## 二、阶段划分与闸门

```
阶段 0  探针（闸门）      ← 决定要不要继续
   ↓ 通过
阶段 1  transport 落地    ← 能跑通一轮对话
   ↓
阶段 2  闸门层适配        ← 四层闸门接上
   ↓
阶段 3  身份获取          ← CDP 取 token + x-hif-dliq
   ↓
阶段 4  原生前台（WPF）   ← 借 gemini 的 AgentHost
   ↓
阶段 5  长期观测          ← 用时间换确定性
```

### 阶段 0｜探针（当前阶段）

**目标**：把「四个缺口」从传闻变成事实，并测出补上之后的存活表现。

| 编号 | 探针 | 交付物 | 需要账号 | 状态 |
|---|---|---|---|---|
| 0.1 | **真实请求画像** | `tools/probe_real_request.py` → 完整 headers + localStorage 快照 | 需要（登录一次） | **脚本已就绪** |
| 0.2 | **curl_cffi 复现** | 补齐四缺口后跑通一轮对话 | 需要 | 待 0.1 |
| 0.3 | **A/B 存活对照** | 裸 TLS vs 伪装 TLS，同频次同内容 | 需要（**建议小号**） | 待 0.2 |

**闸门判据**：

- **0.1 通过** = 抓到 `completion` 与 `create_pow_challenge`，且看清 `x-hif-leim` 的真实形态与来源。
- **0.2 通过** = 补齐缺口后能收到正常 SSE 回复。
- **0.3 是观测项，不阻塞开发** —— 但它是「要不要长期用这条路」的唯一依据。

### 阶段 1｜transport 落地

**目录**：`engine/gad_engine/transport/deepseek_rpc.py`（新写，约 350 行）

- 移植 `DeepSeekApiClient.cs` 的 HTTP + SSE 逻辑到 Python，改用 `curl_cffi`
- PoW 求解器移植（Python 版 Keccak 变体：23 轮、跳过第 0 轮）
- 补齐 `x-hif-leim` / `x-hif-dliq`
- 实现 `Transport` ABC 的四个方法：`start` / `stop` / `health` / `send`

**验收**：`pytest` 单测 + 真实账号跑通一轮。

### 阶段 2｜闸门层适配

- `circuit.py` —— 重写为**事后熔断**（40003 / 限流 / 异常码映射）
- `session.py` —— 改为 `chat_session_id` + `parent_message_id` 链持有
- `gates.py` / `pacing.py` —— 参数重做（DeepSeek 的风控特征不同）
- `protocol.py` / `executor.py` / `router.py` —— **零改动**（已从 gemini 复制）

### 阶段 3｜身份获取

- CDP 读 `localStorage.userToken` + `x-hif-dliq`
- 参照 gemini 的 `browser_login.py`（501 行），可裁剪

### 阶段 4｜原生前台

- WPF（.NET 8），借 gemini 的 `AgentHost` / `EngineClient` / `AgentWindowBase`
- 与 gemini 版同构，后续可互相移植

### 阶段 5｜长期观测

- 连续跑，定期读账号状态与异常码
- 记录：跑多久、什么频率、有没有触发信号
